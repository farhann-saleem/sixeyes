## Implementation notes grounded in the current repo

- Landing components are in [`apps/frontend/src/landing/Landing.tsx`](../apps/frontend/src/landing/Landing.tsx) and [`landing.css`](../apps/frontend/src/landing/landing.css). Existing job polling and phase messages should remain truthful to the async backend.
- Pricing currently presents `price_usd` and `price_pkr` and labels the checkout button **Pay PKR** in [`Pricing.tsx`](../apps/frontend/src/Pricing.tsx). The current SwichNow integration contract in [`spec/19-credits-swichnow.md`](../spec/19-credits-swichnow.md) specifies PKR and server-side amount verification. The owner's new USD instruction supersedes the desired customer experience, but implementation must verify that the active gateway/account can actually settle USD, then update the backend currency/amount contract and tests before removing PKR from checkout. A display-only currency change would misstate the charge.
- The contact number appears in [`Policy.tsx`](../apps/frontend/src/Policy.tsx); the shared [`Footer.tsx`](../apps/frontend/src/Footer.tsx) and landing footer currently have no Contact us link. The policy text mentions an address in the footer that is not present; correct that copy when adding the page.
- Navigation/dropdowns and route definitions are in [`Nav.tsx`](../apps/frontend/src/Nav.tsx). MCP currently has setup/tool entries there and its own [`Mcp.tsx`](../apps/frontend/src/Mcp.tsx). The review's suggestion of a paid “MCP building” offer is **not** an approved feature or price; clarify the existing service first and leave monetization for an owner decision.
